TextShot 첫 번째 버전 개발 로드맵
=================================

1. 프로젝트를 한 문장으로 설명하기
---------------------------------
TextShot은 책에 형광펜, 밑줄 또는 ㄴ·ㄱ 모양으로 표시한 부분을
사진에서 찾아 문장으로 바꾸고, 수정·복사·저장할 수 있는 웹앱이다.


2. 사용자가 이용하는 전체 순서
----------------------------
PC 사용자:
사진 업로드 → 사진 미리보기 → Gemini 추출 → 수정·복사·저장 → 문장 보관함

모바일 사용자:
사진 촬영 또는 사진 선택 → 사진 미리보기 → Gemini 추출
→ 수정·복사·저장 → 문장 보관함


3. 첫 번째 버전에 꼭 넣을 기능
--------------------------------
[사진 입력]
- PC에서는 사진 파일 업로드
- 모바일에서는 지금 촬영하기
- 모바일에서는 앨범에서 사진 선택하기

[사진 확인]
- 선택한 사진 미리보기
- 사진 90도 회전
- 다시 시도 버튼으로 촬영 또는 사진 선택 다시 진행
- 완료 버튼으로 추출 과정 진행
- 너무 큰 사진은 전송 전에 크기 축소

[AI 문장 추출]
- 형광펜으로 표시한 문장 추출
- 밑줄로 표시한 문장 추출
- ㄴ·ㄱ 모양으로 표시한 문장 추출
- 표시된 문장이 없으면 임의의 문장을 만들지 않고 빈 결과 반환

[추출 결과]
- 카드 오른쪽 위에 복사 버튼
- 카드 왼쪽 아래에 수정 버튼
- 카드 오른쪽 아래에 저장 버튼
- 책 제목과 페이지 번호는 선택 입력

[문장 보관함]
- 저장한 문장 목록 보기
- 문장 또는 책 제목으로 검색
- 저장한 문장 수정
- 저장한 문장 복사
- 저장한 문장 삭제

[무료 이용량]
- 무료 사용자는 매월 10장까지 추출
- 표시된 문장이 정상적으로 나온 경우에만 1회 차감
- 표시 없음, 파일 오류, 인터넷 오류, Gemini 오류는 차감하지 않음
- 첫 버전에서는 브라우저 저장소로 사용량 기능을 시험
- 실제 서비스에서는 로그인과 서버 데이터베이스로 사용량 관리

[화면 대응]
- 모바일 세로 화면을 먼저 제작
- 태블릿에서는 카드 2열
- PC에서는 넓은 화면에 맞게 메뉴와 콘텐츠 배치 변경

[디자인 원칙]
- 전체 배경은 흰색
- 글자와 주요 버튼은 검은색
- 카드, 보조 영역, 테두리는 회색
- 첫 번째 버전에서는 초록색, 노란색 등 유채색을 사용하지 않음
- 색상보다 글자 크기, 굵기, 여백으로 중요도를 구분


4. 첫 번째 버전에서 만들지 않을 기능
-----------------------------------
- 회원가입과 로그인
- PC와 모바일 데이터 동기화
- 원본 책 사진 장기 저장
- 친구, 팔로우, 공개 피드
- 문장 공유 이미지 만들기
- 여러 페이지 동시 추출
- 모든 종류의 손그림 표시 자동 인식


5. 화면 구성
------------
[화면 1: 홈]
- TextShot 로고와 짧은 설명
- PC: 사진 업로드 버튼
- 모바일: 사진 촬영 버튼과 사진 선택 버튼
- 최근 저장한 문장 미리보기

[화면 2: 사진 미리보기]
- 선택한 책 사진
- 회전 버튼
- 다시 시도 버튼
- 완료 버튼
- 완료를 누르면 Gemini 추출을 시작한다는 안내

[화면 3: 추출 중]
- 사진 확인 중
- 표시 영역 찾는 중
- 문장 정리 중이라는 안내
- 중복 전송 방지

[화면 4: 추출 결과]
- 추출된 문장 카드
- 오른쪽 위 복사 버튼
- 왼쪽 아래 수정 버튼
- 오른쪽 아래 저장 버튼
- 책 제목, 페이지, 메모 입력

[화면 5: 문장 보관함]
- 저장한 문장 목록
- 검색창
- 최근 저장순 정렬
- 수정, 복사, 삭제 기능

[화면 6: 표시를 찾지 못함]
- 표시된 문장을 찾지 못했다는 안내
- 다시 촬영하기 버튼
- 다른 사진 선택 버튼


6. 실제 개발 순서
----------------

1단계: 기본 뼈대 확인
- index.html이 브라우저에서 열리는지 확인한다.
- style.css와 app.js가 정상적으로 연결됐는지 확인한다.
- 개발자 도구 Console에 오류가 없는지 확인한다.

완료 기준:
- TextShot 제목이 화면에 보인다.
- CSS 배경색이 적용된다.
- Console에 "TextShot 시작"이 보인다.


2단계: 모바일 홈 화면 만들기
- 모바일 세로 화면을 기준으로 홈을 만든다.
- 사진 촬영과 사진 선택 버튼을 만든다.
- 아래쪽에 홈과 보관함 메뉴를 만든다.

완료 기준:
- 작은 스마트폰 화면에서도 가로 스크롤이 생기지 않는다.
- 버튼을 손가락으로 편하게 누를 수 있다.


3단계: PC 반응형 화면 만들기
- 화면이 넓어지면 모바일 하단 메뉴를 PC용 메뉴로 변경한다.
- PC에서는 사진 업로드 버튼을 보여준다.
- 콘텐츠가 지나치게 넓어지지 않게 최대 너비를 정한다.

완료 기준:
- 모바일과 PC에서 같은 HTML을 사용한다.
- 화면 크기에 따라 배치만 자연스럽게 바뀐다.


4단계: 사진 선택과 미리보기
- PC 파일 업로드를 연결한다.
- 모바일 촬영과 앨범 선택을 연결한다.
- 선택한 이미지를 미리보기로 표시한다.
- 회전과 다시 시도 기능을 만든다.
- 완료 버튼의 화면과 상태를 만든다.
- 실제 Gemini 전송은 9단계에서 연결한다.

완료 기준:
- PC와 모바일에서 선택한 사진이 보인다.
- 잘못 고른 사진을 바꿀 수 있다.
- 가로로 누운 사진을 회전할 수 있다.


5단계: 가짜 결과로 추출 카드 만들기
- 아직 Gemini를 연결하지 않는다.
- 가짜 문장 데이터로 결과 카드를 만든다.
- 여러 문장이면 여러 카드가 나오게 만든다.

완료 기준:
- 추출 문장이 카드로 표시된다.
- 카드 배치가 모바일과 PC에서 깨지지 않는다.


6단계: 수정과 복사 기능
- 수정 버튼을 누르면 카드 안에서 문장을 편집한다.
- 수정 완료와 취소 버튼을 제공한다.
- 복사 버튼을 누르면 클립보드에 문장을 복사한다.
- 복사 후 잠시 "복사됨" 상태를 보여준다.

완료 기준:
- 수정한 문장이 카드에 반영된다.
- 복사한 문장을 다른 곳에 붙여넣을 수 있다.


7단계: 저장과 문장 보관함
- localStorage에 문장, 책 제목, 페이지, 메모, 표시 종류, 날짜를 저장한다.
- 원본 사진은 첫 번째 버전에서 저장하지 않는다.
- 보관함에서 검색, 수정, 복사, 삭제할 수 있게 한다.

완료 기준:
- 브라우저를 새로고침해도 저장한 문장이 남아 있다.
- 문장 삭제 전 확인 메시지가 나온다.
- 보관함이 비었을 때 안내 화면이 나온다.


8단계: Gemini 서버리스 함수 준비
- Gemini API 키를 브라우저 JavaScript에 넣지 않는다.
- API 키는 배포 서비스 환경변수에 저장한다.
- 서버리스 함수에서 이미지 종류와 용량을 검사한다.
- Gemini 응답을 정해진 JSON 형태로 돌려준다.

완료 기준:
- GitHub 코드에 실제 API 키가 없다.
- 잘못된 파일과 너무 큰 파일을 거절한다.


9단계: 실제 Gemini 추출 연결
- 사진과 추출 규칙을 Gemini에 전달한다.
- 형광펜, 밑줄, ㄴ·ㄱ 표시만 우선 지원한다.
- 문장을 요약하거나 번역하지 않고 원문 그대로 받는다.
- 표시가 없으면 빈 배열을 받는다.

완료 기준:
- 실제 사진을 전송하면 결과 카드가 만들어진다.
- 실패하면 사용자가 이해할 수 있는 안내가 나온다.


10단계: 로딩과 오류 처리
- 분석 중에는 버튼을 다시 누르지 못하게 한다.
- 인터넷 오류, 파일 오류, AI 오류를 구분한다.
- 어려운 기술 용어 대신 다시 시도할 방법을 알려준다.

완료 기준:
- 사용자가 현재 기다려야 하는지 다시 촬영해야 하는지 알 수 있다.


11단계: 실제 사진 테스트
- 형광펜 사진 10장
- 밑줄 사진 10장
- ㄴ·ㄱ 표시 사진 5장
- 아무 표시도 없는 사진 5장

완료 기준:
- 표시된 사진 10장 중 8장 이상 성공을 목표로 한다.
- 표시 없는 사진에서 임의의 문장을 추출하지 않는다.
- 잘못 추출된 글자는 사용자가 수정할 수 있다.


12단계: 배포와 포트폴리오 정리
- README에 프로젝트를 만든 이유를 작성한다.
- 모바일과 PC 화면 이미지를 추가한다.
- 어려웠던 문제와 해결 방법을 기록한다.
- 실제 사용 가능한 배포 주소를 README에 연결한다.
- GitHub 프로필에 textshot 저장소를 고정한다.

1. 프로젝트 초기 구조 생성

3. PC 반응형 레이아웃 추가

6. 추출 결과 카드 UI 구현
7. 문장 수정 및 복사 기능 추가
8. 문장 보관함 저장 기능 구현
9. 보관함 검색, 수정, 삭제 기능 추가
10. Gemini 서버리스 함수 연결
11. 로딩과 오류 처리 추가
12. 반응형 UI와 접근성 개선
13. README와 프로젝트 이미지 추가


8. GitHub에 올리기 전 확인 목록
-------------------------------
- .env 파일이 Git에 포함되지 않았는가?
- Gemini API 키가 코드에 적혀 있지 않은가?
- git status로 올라갈 파일을 확인했는가?
- git diff --cached로 커밋 내용을 확인했는가?
- 커밋 메시지가 변경 내용을 설명하는가?


9. 오늘 가장 먼저 할 일
----------------------
1. index.html을 브라우저에서 연다.
2. TextShot 제목과 배경색이 보이는지 확인한다.
3. 모바일 홈 화면의 사진 촬영·사진 선택 버튼을 만든다.
4. PC 화면에서 사진 업로드 버튼으로 바뀌게 만든다.
5. 여기까지 정상 작동하면 첫 커밋을 만든다.

첫 번째 작은 목표:
PC에서는 사진을 업로드하고, 모바일에서는 촬영하거나 사진을 선택한 뒤,
선택한 사진이 미리보기 화면에 나타나게 만든다.


10. 첫 번째 버전 완성 기준
-------------------------
- PC에서 사진을 업로드할 수 있다.
- 모바일에서 촬영하거나 사진을 선택할 수 있다.
- 사진을 확인하고 회전할 수 있다.
- Gemini가 형광펜, 밑줄, ㄴ·ㄱ 표시 문장을 추출한다.
- 사용자가 추출 문장을 수정하고 복사할 수 있다.
- 사용자가 문장을 웹앱 보관함에 저장할 수 있다.
- 저장한 문장을 검색, 수정, 복사, 삭제할 수 있다.
- 모바일, 태블릿, PC 화면에서 사용할 수 있다.
- 실제 API 키가 GitHub에 공개되지 않는다.
